## Decision log

### D1 — MCP tool conditional registration: the plan assumes a mechanism the wrapper doesn't have
**Found:** the AC says `get_git_url` should be "registered only when the feature is enabled." The
MCP server (`src/mcp/__main__.py`) serves a single module-level `TOOLS` list, always the same,
regardless of any server-side flag — there is no existing precedent for a conditionally-listed
tool anywhere in this codebase, and no mechanism for the MCP wrapper (a separate stdio process,
often pointed at a remote `MDREVIEW_BASE` it has no other channel to) to learn the HTTP backend's
`MDREVIEW_ENABLE_GIT_HISTORY` value before `tools/list` responds. `_tools_hash()` is also the
staleness comparand between a running wrapper and the repo's on-disk surface; making TOOLS
environment-conditional would break that contract.
**Decided:** register `get_git_url` statically, exactly like every other tool (including
`create_review`'s `kind="latex"`, which is the existing precedent for "advertised unconditionally,
enforced server-side at call time"). Calling it against an instance with the flag off gets a plain
404 through the normal HTTP path (no route registered). AC bullet is NOT fully met as literally
worded; this is the nearest-faithful implementation given the actual architecture.
**Falsified if:** a future MCP protocol version adds per-connection capability negotiation the
wrapper could use to filter TOOLS at `initialize` time — worth revisiting then.

### D2 — token-in-URL: the plan's auth mechanism is wrong as written
**Found:** the design doc says a git client's `https://<token>@host/git/<rid>.git` URL "maps onto
[the bearer-token check] directly." It doesn't: a userinfo-in-URL makes git send
`Authorization: Basic base64(token:)`, not `Bearer <token>`. `mdreview.access.ProxyBearerIdentity`
only recognizes `Bearer `. A token embedded in the URL as designed would silently 401 against a
require-auth instance.
**Decided:** `get_git_url` returns a tokenless URL (`{base}/git/{rid}.git`); the tool description
documents the working incantation for a require-auth instance: `git -c
http.extraheader="Authorization: Bearer <token>" clone <url>`. Not verified end-to-end against a
REQUIRE_AUTH=1 instance (this run's local check is REQUIRE_AUTH off, by design — see the PR/issue
comment's "what was NOT validated").
**Falsified if:** an owner run against a hosted/staging instance with a real Bearer token shows the
extraheader form doesn't reach `_authz_read` correctly.

### D3 — materialization cap applies only to the cold build, never re-windows
**Decided:** `MDREVIEW_GIT_MATERIALIZE_MAX_ROUNDS` decides the historical window ONCE, the first
time a review's bare repo is ever built (skip-ahead if already over the cap at that moment).
After that, new rounds append one at a time as they arrive, uncapped per call. The alternative
(re-evaluate the window on every call, dropping old commits as new ones arrive) would mean
rebuilding commits the design explicitly calls immutable-once-built ("historical rounds are
immutable once archived — built once, never rebuilt"). This is the only reading consistent with
that constraint; documented in `gitcache.py`'s module docstring for the owner to veto.
**Falsified if:** the owner wants a permanently-shallow window that keeps sliding forward on a
long-lived, frequently-cloned review — that needs a different (rebuild-tolerant) design.

### D4 — the runnable check clones over real HTTP, not a file-path clone
**Decided:** `tests/git_history_selfcheck.py` boots a real `python -m mdreview` subprocess with
`MDREVIEW_ENABLE_GIT_HISTORY=1`, drives a review through two `PUT /source` rounds + one comment,
and does an actual `git clone http://127.0.0.1:<port>/git/<id>.git` — the only way to exercise
`routes.py`'s `git http-backend` CGI proxy end to end (a `file://` clone would only prove
`gitcache.py`'s plumbing, not the HTTP route). It also boots a second instance with the flag off
and asserts both `/git_url` and the raw git route 404, proving the byte-identical-when-off
contract. Verified twice locally (git plumbing validated first via a throwaway `.scratch/` probe,
deleted before commit).

  principle fill the volume via `.git-cache` with the flag on. Worth a follow-up if this ships.
